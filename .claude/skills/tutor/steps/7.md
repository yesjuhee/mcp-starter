# 7. 개선본 둘러보기

## 목표

같은 MCP 서버를 더 잘 만든 버전(`improved/`)을 함께 보며, 지금까지 겪은 장면이 어떻게 개선되는지 본다.
이 단계를 시작하면 `improved/`가 열린다.

## 처음 나오는 용어

없음

## 해볼 것

1. "같은 MCP 서버를 더 잘 만들면 어떻게 될까요?"로 시작한다. 지금까지 써보며 이상했던 점이 있었는지 한 번만 가볍게 묻는다. 없어도 바로 넘어간다.
2. `improved/server.py`를 함께 연다. 맨 위 설명에 개선 1~5가 있고, 코드에 `개선 N` 주석이 있다.
3. 개선을 하나씩 본다. 각 개선을 **학습자가 앞 단계에서 겪은 장면**과 연결한다. "이어지는 장면"의 Desktop 장면은 6단계를 실제로 했을 때만 연결한다. 건너뛰었다면 Desktop 화면을 단정하지 말고, 코드에서 무엇이 바뀌었는지(title, mime_type 등)로만 설명한다.

   | | 무엇이 문제였나 | 어떻게 개선했나 | 이어지는 장면 |
   |---|---|---|---|
   | 1 | "전체 목록" 도구가 없어 모델이 빈 키워드("")로 우회. 빈 문자열이 모든 이름에 포함돼 우연히 성공 | `list_missions()`를 따로 둠 | 4단계, 6단계의 전체 목록 요청 |
   | 2 | Prompt 인자에 안내와 검증이 없어 아무 값이나 들어감 | 인자 설명, 자동완성, 잘못된 값이면 "다시 물어봐" 문장 | 5단계, 6단계 Prompt 입력 |
   | 3 | Resource가 JSON인데 일반 텍스트로 취급됨 | `mime_type="application/json"` | 6단계에서 TXT로 첨부된 장면 |
   | 4 | 메뉴에 함수 이름이 그대로 보임 | `title`로 사람이 읽을 이름 | 6단계 메뉴의 "All missions" |
   | 5 | 코스를 자유 문자열로 받아 "spring" 같은 값이면 빈 결과 | 자바, 스프링, 리액트 중에서만 고르게 함 | 3단계 인자를 모델이 정한 장면 |

4. `improved/`에서 `uv run smoke_test.py`를 실행해 개선 결과를 함께 본다.
5. 마무리로 `improved/`는 **정답이 아니라 개선안 하나**라고 말한다. 직접 고쳐보고 싶다면 `server/server.py`에서 해볼 수 있다고 알린다 (선택. 고친 뒤 써보려면 Claude Code를 재시작해야 한다).

## 완료 조건

- 개선 1~5를 함께 봤다
- `improved/` smoke test가 성공했다

## 자주 헷갈리는 지점

- **Prompt에서 잘못된 값을 예외로 막으면 안 되나**: 막을 수는 있지만 예외 메시지가 학습자에게 그대로 가지 않고 "Error rendering prompt ..." 같은 일반 메시지로 바뀐다. 그래서 개선안은 거절 대신 "다시 물어봐줘" 문장을 돌려준다.
- **smoke test에 `rejected arguments` 줄이 보인다**: 개선 5를 확인하려고 일부러 "spring"을 넣어 거절된 기록이다. 정상이다.

## 하지 않는 것

- 학습자에게 이상한 점 목록을 만들라고 요구하지 않는다.
- 직접 고치기를 필수처럼 안내하지 않는다.
