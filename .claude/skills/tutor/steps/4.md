# 4. Resource 써보기

## 목표

Resource가 대화에 들어오는 두 가지 길을 써보고, calls.log로 확인한다.

## 처음 나오는 용어

없음. 3단계의 등장인물 이름을 그대로 쓴다.

## 해볼 것

1. **첨부 없이 묻기**: 학습자에게 "초록스터디 전체 미션 목록 보여주세요"라고 묻게 한다. 코치는 평소처럼 답하고, 답한 뒤 어떤 길로 데이터를 가져왔는지 calls.log로 보여준다. Tool을 써도, Resource를 읽어도 둘 다 관찰 결과다.
   - Tool을 골랐다면 선택 실험으로 "이번엔 Resource를 직접 읽어서 보여줘"라고 요청해보게 한다. 모델이 Resource를 읽는 길을 볼 수 있다
2. **@로 첨부하기**: 입력창에 `@`를 치고 목록에서 cholog-hello 항목을 골라 첨부한 뒤 "이 중에 스프링 미션은 뭐예요?"라고 묻게 한다.
3. 코치는 답한 뒤, 이번엔 **코치가 아무것도 부르지 않았고**, 학습자의 질문과 함께 미션 목록 전체가 이미 붙어서 왔다는 걸 알려준다.
4. calls.log에서 1번이 남긴 줄과 @ 첨부가 남긴 `RESOURCE` 줄을 함께 본다. 둘 다 `RESOURCE`라면 똑같아 보인다.
5. 등장인물 이름으로 차이를 정리해준다.
   - 첨부 없이: 모델이 어떤 기능을 쓸지 판단해서 요청했고, Claude Code가 MCP 서버를 불렀다
   - @ 첨부: 학습자가 골랐고, Claude Code가 질문을 모델에게 보내기 전에 MCP 서버에서 읽어 질문에 붙였다. 모델은 관여하지 않았다
   - MCP 서버는 누가 왜 읽는지 모른다. 그래서 두 줄이 똑같다
6. 선택: 3단계처럼 `MCP_STARTER_OBSERVE=1 claude`로 연 새 세션에서 "초록스터디 전체 미션 목록 보여주세요"를 해보면, 코드를 모르는 모델은 어떤 길을 고르는지 볼 수 있다.

## 완료 조건

- calls.log에 1번 질문이 남긴 줄이 있다 (`TOOL`이든 `RESOURCE`든)
- calls.log에 @ 첨부가 남긴 `RESOURCE` 줄이 있다

## 자주 헷갈리는 지점

- **Resource는 결국 뭔가**: 파일을 `@`로 대화에 붙이는 것과 같다. MCP 서버가 내준 데이터를 같은 방식으로 붙일 수 있는 길이다. 스펙의 정의는 "Context and data, for the user **or** the AI model to use"다.
- **모델이 Resource를 스스로 읽을 수 있나**: 스펙은 학습자와 모델 모두에게 열어두고, 실제로 누가 쓰게 할지는 AI 앱이 정한다. Claude Code는 모델에게 Resource를 읽는 방법을 준다. 다른 AI 앱은 다를 수 있다. 확인하지 않은 앱에 대해 단정하지 않는다.
- **첨부하면 얼마나 들어가나**: 전체가 통째로 들어간다. 데이터가 크면 그만큼 대화 공간을 차지한다.
- **"MCP 서버가 끼워 넣었다는 거냐"**: 아니다. 끼워 넣은 건 Claude Code다. MCP 서버는 요청이 오면 데이터를 돌려줄 뿐 질문을 보지 못한다.

## 하지 않는 것

- 두 길의 차이를 학습자에게 설명해보라고 묻지 않는다. 코치가 정리해준다.
- "제 쪽에 도착했다" 같은 표현을 쓰지 않는다. 화면과 calls.log로 말한다.
