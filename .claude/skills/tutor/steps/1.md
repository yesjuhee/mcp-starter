# 1. 서버 둘러보기

## 목표

`server/server.py`의 구조를 이해한다. 세 가지 기능의 차이를 정확히 아는 건 이 단계의 목표가 아니다. 그건 써보면서 알게 된다.

## 처음 나오는 용어

Tool, Resource, Prompt, 입력 스키마, calls.log, 스펙

## 해볼 것

1. 0단계에서 권한 대로 server.py를 훑어봤는지 묻는다. 봤다면 **소감이나 궁금한 점부터** 듣는다. 안 봤다면 같이 연다.
2. 아래 덩어리 순서로, 한 덩어리씩 짧게 설명한다. 덩어리마다 학습자의 반응이나 질문을 보고 다음으로 간다.
   - 서버 객체: `MCPServer(name="cholog-hello")`. 아래 기능들을 여기에 등록한다
   - 데이터: `MISSIONS`. 데이터베이스 대신 쓰는 딕셔너리. 미션 이름은 실제, `top_topic`은 예시 값
   - 기록: `log()`. 호출될 때마다 calls.log에 한 줄 남긴다. 앞으로 계속 볼 관찰 도구
   - 기능 세 개: `@mcp.tool()`, `@mcp.resource(...)`, `@mcp.prompt()`
3. 기능 세 개를 볼 때 짚을 것
   - docstring이 그대로 기능 설명이 되고, 타입 힌트가 그대로 입력 스키마가 된다
   - 0단계 smoke test 출력과 `server/calls.log`를 지금 보여주며 "코드의 세 함수가 이렇게 한 번씩 불렸다"고 연결한다
   - 스펙의 정의 세 줄을 함께 본다 ([Specification 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28))
     - Resources: Context and data, for the user or the AI model to use
     - Prompts: Templated messages and workflows for users
     - Tools: Functions for the AI model to execute
4. 마무리: "세 기능의 차이가 아직 흐릿해도 괜찮아요. 다음 단계부터 이 서버를 쓰는 사람 입장에서 직접 써보면서 알게 될 거예요."

## 완료 조건

- server.py를 기능 세 개까지 함께 봤다

## 자주 헷갈리는 지점

- **데코레이터가 뭔가**: 함수에 "이건 Tool로 등록해줘" 같은 표시를 붙이는 것. 학습자 배경에 맞는 비유로 설명한다 (예: Java/Spring의 어노테이션).
- **인터넷 예제는 FastMCP를 쓰던데**: mcp 1.x 시절 이름이다. 2.x에서 MCPServer로 바뀌었다. 이 학습 세트는 mcp 2.2.0 기준이다.
- **`mcp.run(transport="stdio")`는 무엇인가**: 2단계에서 연결하면서 본다고 넘긴다.

## 하지 않는 것

- 세 기능의 차이를 설명해보라고 묻지 않는다.
- 코드 전체를 한 응답에 몰아서 설명하지 않는다.
- 코드의 허점을 먼저 지적하지 않는다. 학습자가 이상하다고 하면 반기고 7단계에서 같이 보자고 한다.
