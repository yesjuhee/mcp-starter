# 3. Tool 써보기

## 목표

도구 이름을 말하지 않은 질문에 모델이 Tool을 스스로 골라 부르는 걸 보고, calls.log로 확인한다.

## 처음 나오는 용어

모델. 이 단계에서 **등장인물 소개**를 처음이자 한 번만 한다.

## 해볼 것

1. 학습자에게 도구 이름을 말하지 말고 물어보라고 한다. 예: "초록스터디 자바 미션 뭐 있어요?"
2. 코치는 평소처럼 답한다. 필요하면 도구를 쓴다.
3. 답한 뒤 calls.log 마지막 줄을 함께 보고, 등장인물 그림으로 무슨 일이 있었는지 보여준다. 텍스트 그림으로 그린다.

   ```
   학습자 ──질문──▶ Claude Code ──질문 + 쓸 수 있는 도구 목록──▶ 모델
                                                                  │
   학습자 ◀──답변── Claude Code ◀──"find_missions를 '자바'로 불러줘"──┘
                         │  ▲
            실제 호출 ────▼  │──── 결과 (calls.log에 한 줄)
                       MCP 서버
   ```

   - 모델은 도구를 직접 실행하지 않는다. "이 도구를 이 값으로 불러줘"라고 요청할 뿐이다
   - 실제로 MCP 서버를 부른 건 Claude Code다
   - 인자 '자바'는 모델이 도구 설명과 입력 스키마를 보고 질문에서 골라 넣었다
4. 호출 전에 허용 창이 떴는지 학습자에게 물어본다.
5. 선택: "저는 아까 server.py를 같이 읽어서, 설명만 보고 도구를 고른 건지 확인하기 어려워요." 원하면 **새 터미널에서 같은 폴더로 이동한 뒤 `MCP_STARTER_OBSERVE=1 claude`로** Claude Code를 하나 더 열고 같은 질문을 해보게 한다. 그 세션은 코드를 읽은 적이 없고, 관찰용이라 진행 상태를 바꾸지 않는다. 끝나면 calls.log에 줄이 하나 더 생겼는지 같이 본다.

## 완료 조건

- calls.log에 이번 질문으로 생긴 `TOOL` 줄이 있다

## 자주 헷갈리는 지점

- **인자는 누가 정하나**: 모델이 도구 설명과 입력 스키마(`keyword: string`)를 보고 질문에서 알맞은 값을 골라 채운다. 학습자 배경에 맞는 비유로 설명한다 (예: API 문서를 읽고 요청을 직접 만들어 보내는 클라이언트).
- **허용 창이 안 떴다**: 학습자의 권한 설정에 따라 다르다. 기본 설정이면 처음 한 번은 묻는 것이 일반적이다.
- **MCP 클라이언트가 뭐냐고 물으면**: Claude Code 안에서 MCP 서버와 연결을 맡는 부분이라고 답한다. 등장인물로 따로 세우지 않는다.

## 하지 않는 것

- 학습자에게 방금 일을 설명해보라고 묻지 않는다.
- 학습자가 결과가 이상하다고 하면 원인을 먼저 말하지 않는다. 좋은 관찰이라고 반기고 7단계에서 같이 보자고 한다. 원인을 직접 물으면 답한다.
