# 2. Claude Code에 연결

## 목표

MCP 서버를 Claude Code에 등록하고, 연결된 것을 눈으로 확인한다.

## 처음 나오는 용어

stdio, 자식 프로세스

## 해볼 것

1. 등록 명령을 보여주고 뜻을 짧게 풀어준다. `server/` 절대 경로는 코치가 확인해서 채운다. 경로를 채웠다는 말은 하지 않는다.

   ```bash
   claude mcp add cholog-hello --scope local -- uv run --directory "<server 절대 경로>" server.py
   ```

   - `cholog-hello`: Claude Code 안에서 부를 이름
   - `--scope local`: 이 폴더에서만, 이 사용자에게만 등록
   - `--` 뒤: Claude Code가 MCP 서버를 실행할 명령
2. 이 명령이 Claude Code 설정을 바꾼다는 것과 되돌리는 방법(`claude mcp remove cholog-hello -s local`)을 알리고, 실행해도 되는지 묻는다.
3. 실행 후 `claude mcp list`로 Connected를 확인한다.
4. 재시작을 안내한다: "등록된 서버를 사용하려면 세션을 재시작해야 합니다." 지금 세션을 종료하고 같은 폴더에서 `claude --continue`로 다시 열면, 진행 상황은 그대로 이어진다고 알린다.
5. 다시 열리면 학습자에게 `/mcp`를 입력해 cholog-hello 화면을 보게 한다. 코치도 자기가 쓸 수 있는 도구 목록에 `find_missions`가 생겼는지 확인해서 알려준다.

## 관찰 포인트

- Claude Code가 세션을 시작할 때 등록된 명령으로 MCP 서버를 실행한다. 학습자가 직접 서버를 켠 적이 없다는 점을 짚는다.
- `/mcp` 화면에 Capabilities로 tools, resources, prompts가 보인다.

## 완료 조건

- 재시작 후 `/mcp`에서 cholog-hello가 connected
- 코치가 쓸 수 있는 도구 목록에 `find_missions`가 있다

## 자주 헷갈리는 지점

- **MCP 서버를 켠 적이 없는데 떠 있나**: Claude Code가 세션을 시작할 때 MCP 서버를 자식 프로세스로 실행하고, 세션 내내 같은 프로세스가 요청을 처리한다. 세션이 끝나면 같이 종료된다. 호출마다 새로 뜨는 방식도, 항상 켜져 있는 서버도 아니다. 세션을 두 개 열면 MCP 서버도 두 개 뜬다.
- **claude.ai 웹 채팅에도 붙일 수 있나**: 지금 방식(stdio)은 내 컴퓨터에서 프로그램을 실행하는 방식이라 웹은 연결할 수 없다. 웹에서 쓰려면 MCP 서버를 인터넷에 HTTP로 배포해야 한다.
- **/mcp 화면에 Tool 개수만 보인다**: Claude Code 화면이 Tool 위주로 보여줄 뿐, Capabilities 줄에서 세 기능을 다 제공한다는 걸 알 수 있다.

## 하지 않는 것

- 학습자 동의 없이 등록 명령을 실행하지 않는다.
- 재시작 전에 `complete 2`를 실행하지 않는다.
