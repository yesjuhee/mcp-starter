# 5. Prompt 써보기

## 목표

Prompt를 직접 실행해보고, 지금까지 써본 세 기능을 함께 정리한다.

## 처음 나오는 용어

없음

## 해볼 것

1. 입력창에 `/`를 치고 cholog-hello의 `mission_briefing`을 찾게 한다. (보통 `mcp__cholog-hello__mission_briefing`)
2. 미션 ID를 넣어 실행하게 한다. 예: `racingcar`. 다른 값을 넣어보고 싶으면 자유롭게 해도 된다고 말한다.
3. 코치는 받은 메시지에 답한 뒤, **이번 MCP 서버의 Prompt는** 학습자 메시지 한 개를 만들어 주고, 그래서 학습자가 직접 친 메시지와 같은 모양으로 들어왔다고 알려준다. 스펙상 Prompt는 여러 메시지, 모델 쪽 메시지도 담을 수 있다는 점도 덧붙인다.
4. calls.log의 `PROMPT` 줄을 함께 본다. Prompt 문장은 Claude Code에 저장된 게 아니라 실행할 때마다 MCP 서버에서 받아온다는 걸 짚는다.
5. 세 기능 비교표를 **함께** 채운다. 코치가 지금까지 학습자가 한 말과 본 장면으로 초안을 만들고, 학습자에게 고치고 싶은 데가 있는지 묻는다.

   | | 누가 꺼내나 | 대화에 어떻게 들어오나 |
   |---|---|---|
   | Tool | 모델이 판단해서 | 모델이 요청한 결과로 |
   | Resource | 학습자가 첨부하거나, 모델이 판단해서 | 첨부면 질문에 붙어서, 모델이 읽으면 결과로 |
   | Prompt | 학습자가 메뉴에서 골라서 | MCP 서버가 만든 메시지로 (이번 서버는 학습자 메시지 하나) |

## 완료 조건

- calls.log에 `PROMPT` 줄이 있다
- 비교표를 함께 정리했다

## 자주 헷갈리는 지점

- **Prompt는 왜 쓰나**: 좋은 질문을 미리 만들어 메뉴로 나눠주는 기능이다. 무엇을 어떻게 물어야 할지 고민하지 않아도 된다. 템플릿 안에 "이 도구를 써서 답해줘"를 넣어 질문과 도구 사용을 묶을 수도 있다.

## 하지 않는 것

- 비교표를 학습자에게 혼자 채우라고 하지 않는다.
- 학습자가 이상한 값을 넣어 이상한 결과가 나와도 원인을 먼저 말하지 않는다. 7단계에서 같이 본다. 원인을 직접 물으면 답한다.
